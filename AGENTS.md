# План и правила учебного проекта UI-автотестов

## Назначение и ведение плана

Этот файл — постоянный источник согласованных решений, статусов и открытых вопросов между сессиями агента. Цель проекта — постепенно добавить TestBase, независимые сценарии, Page Object, Allure Report 3, GitHub Actions, Telegram и Jenkins, сохраняя существующий Java-стек.

- Перед работой читать этот файл, проверять актуальные файлы и состояние git.
- Выполнять только подтверждённую пользователем фазу. Перед фазой объяснять изменения и их цель; после неё останавливаться до следующего подтверждения.
- После фазы обновлять здесь статус, решения, команды, результаты, ограничения и открытые вопросы. Изменения плана включать в коммит своей фазы.
- Отмечать пункты выполненными только по фактическим результатам; отличать собственную проверку от отчёта предыдущего исполнителя.
- План не заменяет проверки: написанный конфиг не означает проверенную интеграцию.

## Общие ограничения

- Объяснения — на русском; код, идентификаторы и сообщения коммитов — на английском.
- Следовать существующим конвенциям; не менять стек без согласования и не добавлять файлы или зависимости без необходимости.
- Не менять и не коммитить чужой WIP. После завершённой и проверенной фазы создавать отдельный логичный коммит только со своими изменениями.
- Не делать push, не переписывать историю и не менять инфраструктуру без явного разрешения.
- Перед деструктивными действиями запрашивать подтверждение конкретной операции.
- Не коммитить секреты, отчёты, результаты тестов и node_modules. Не просить значения секретов в чат.
- Не скрывать ошибки ретраями, отключением тестов или безусловным continue-on-error.
- Использовать ожидания Selenide вместо sleep. Не обходить антибот-защиту GitHub.
- При недоступности браузера, сети, CI или Jenkins сообщать об этом и перечислять непроверенные части.
- Не обходить запреты чтения игнорируемых файлов другим инструментом; запрашивать помощь при блокировке.
- При смене модели оставлять handoff: решения, файлы, команды, результаты и открытые вопросы.

## Согласованные решения

- Java 21 через Gradle Java toolchain; Gradle Wrapper 9.6.0, bin-дистрибутив.
- Selenide 7.18.2, JUnit Jupiter 6.1.3; исходно разрешённый Selenium — 4.49.0. Версии зависимостей без согласования не менять.
- Defaults: baseUrl=https://github.com, browser=chrome, browserSize=1920x1080, headless=false.
- Переопределение через -DbaseUrl, -Dbrowser, -DbrowserSize, -Dheadless с явной передачей только этих свойств из Gradle в JVM тестов.
- В CI явно передавать headless=true.
- Page Object: fluent API; проверки в should…-методах страниц; private final SelenideElement-поля; имена методов описывают пользовательские действия.
- Отдельные компоненты выделять только при реальном повторении блоков. Не добавлять BasePage, фабрики и сложную конфигурационную систему без необходимости.

2. Проверки действительно запущены и результаты зафиксированы.
3. Временная диагностика удалена, ограничения и блокеры перечислены.
4. Этот план обновлён без превращения предположений в подтверждённые результаты.
5. Свои изменения закоммичены; чужой WIP не затронут.
6. Работа остановлена до подтверждения следующей фазы.
